# A new preparation phase in the existing project

`same_project_successor_phase_v1` separates an immutable expired run from a
genuinely new, preparation-only phase. It does not create another project/brain,
replace a host, relabel a replay or make the original phase executable again.

## Narrow supported lineage

Require the complete canceled-Play disposition, exact closed original planning
preflight-refusal lineage and the positively completed, closed post-disposition
maintenance load. Unknown, failed, partial, stopped, unlisted or changing records
cannot acquire this exception. Read a historical maintenance only with the exact
allowlisted immutable PR-179 Python source; never execute that old implementation.
Its original PR-176 lineage remains separately pinned and validated.

Keep the same registered workspace, single brain, dual project IDs, checkout,
actually issued live host/package/socket, both binding files/epochs, native
history prefixes and credential metadata. Native credential bytes must never be
read/copied/refreshed. Old ledgers, sidecars, requests, receipts, gaps, original
expiry and repository holds are unchanged. No historical outcome becomes safe.

This path applies only after original expiry. The old same-phase planning and
ordinary standard-control fences remain intact, including after successful
maintenance. Existing disjoint-successor, strict Harness and original recovery
contracts are unchanged.

## New scope, not new capacity or a renewed old clock

An exact new review contains a deterministic distinct phase ID, 1–24 hours
(normally 24), an explicit one-turn planning allowance (normally 10,000 tokens),
zero workers and no repository-write authority. It identifies the old run as
its immutable predecessor. It is a preparation proposal, not worker Play.
These are cooperative scope limits, not a new OS sandbox policy or attestation
that arbitrary native effects are impossible. Unexpected effects remain unknown;
no cleanup or pilot-acceptance claim follows from a proposal.

The reviewed clock starts once at confirmation in the external owner intent;
waiting to review starts no clock. Duration and intent are checked before
subscription, usage collection, turn start and observer operations. They cannot
be renewed by a read, second approval, source change or new directory. The old
run's expiry is never edited or used as this new clock.

Carry both retained cumulative usage observations and their exact session
vectors/sample times forward. Collect actual local numeric evidence once, only
after original subscription ownership. Apply the original total/brain/reserve
caps to the new allowance plus all observed consumption; no zero baseline,
refund, reset or extra budget follows from a phase ID. New evidence must remain
under the existing 120-second freshness limit at send. Gaps, regressions or
staleness stop without resampling. The cooperative one-turn ceiling is not a
provider billing cap. Post-turn lifetime consumption is not invented from the
pre-turn report; later accounting remains a separate observation.

## One connection and one new instruction

Stop older writers and verify private database/sidecar/binding/lineage backups
before exact confirmation. One permanent canonical phase directory is keyed to
the original ledger identity and Play, independent of review IDs, source and
host. Its owner and consumer records remain separate. Partial ownership consumes
the phase; no recursive successor, host migration, adoption or retry is supplied.

On one foreground connection, repeat exact native project/brain/latest-original-
interrupted-turn, actual loaded restricted policy and complete empty **current**
tracked-terminal reads. Claim before one atomic already-loaded-only subscription.
Keep that same connection through one usage collection and one new inert receipt/
proposal turn. No `thread/resume`, new thread/project, persistent keeper, reconnect,
automatic native permission response or cancellation is permitted.

The fixed sandbox helper receives only its new checkout-local data mailbox,
never the ledger, registry, socket or controller credential. A new explicit
receipt and bounded inert `summary`/`nextSteps` proposal are separately retained.
Native completion alone is not a receipt or phase result. Stop, drift, permission
requests, unknown delivery, stale usage and either lost original owner/clock fence
the path without retry. Close the original connection afterwards.

Current empty trackers do not prove historical cleanup. Current and historical
terminal safety remain unknown. Repository holds and ordinary execution fences
are retained even when the proposal completes. Neither completion nor this source
permits worker dispatch, old Play/recovery replay, Resume, merge, closeout,
ownership release, phase success or pilot acceptance.

## Diagnose before requesting execution approval

Preparation, backup and status are file-only. The explicit diagnostic repeats
only metadata reads and grants no subscription, claim, usage collection or turn.
`notLoaded` returns `brain_not_loaded_no_reload_authorized`, with unknown policy
and terminals. Do not turn old maintenance's historical loaded observation into
current ownership or create a live keeper to make a prerequisite true.

An unloaded runtime cannot execute under a no-reload constraint. Do not ask for
a futile phase confirmation or invent another project. The supported prerequisite
is an independently permitted, already-loaded runtime; this control supplies no
way to load one. A live pilot can therefore remain blocked even after complete
source/disposable qualification. Report that boundary directly.

## Operator interface

```text
python3 -B -m orchestrator.successor_phase --platform PLATFORM --workspace WORKSPACE prepare COMPLETED_MAINTENANCE_REVIEW --maintenance-source EXACT_FROZEN_PR179_SOURCE --duration-hours 24 --max-tokens 10000
python3 -B -m orchestrator.successor_phase --platform PLATFORM --workspace WORKSPACE inspect NEW_PHASE_REVIEW
python3 -B -m orchestrator.successor_phase --platform PLATFORM --workspace WORKSPACE backup NEW_PHASE_REVIEW NEW_PRIVATE_BACKUP --writers-stopped
python3 -B -m orchestrator.successor_phase --platform PLATFORM --workspace WORKSPACE confirm NEW_PHASE_REVIEW --confirm-hash EXACT_NEW_HASH --backup NEW_PRIVATE_BACKUP --writers-stopped
python3 -B -m orchestrator.successor_phase --platform PLATFORM --workspace WORKSPACE status NEW_PHASE_REVIEW
python3 -B -m orchestrator.successor_phase --platform PLATFORM --workspace WORKSPACE stop NEW_PHASE_REVIEW --confirm-hash EXACT_NEW_HASH
```

Save the closed request, not its preview wrapper. Review validity ends on scope
changes, not a short timer. The source adds no browser write route or new page.
No installation or live confirmation is included in source delivery.

## Disposable qualification

```text
python3 -B scripts/qualify_canceled_continuation.py --package EXACT_PACKAGE --evidence EMPTY_PRIVATE_DIRECTORY --successor-phase
python3 -B scripts/qualify_canceled_continuation.py --package EXACT_PACKAGE --evidence ANOTHER_EMPTY_PRIVATE_DIRECTORY --phase-unloaded
```

The positive compiled fixture genuinely cancels an original native turn, performs
the old and maintenance loads, then exercises the production new phase on an
independently fixture-owned warm runtime. That explicit extra fixture subscription
is a prerequisite, not a production keeper/handoff or permission to create one
live. The phase itself uses one connection/subscription/new turn and no reload.
The negative fixture actually unloads and verifies zero phase effects/claims.
Old ledger/accounting, launch provenance, historical preflight refusal and expired
wall clock are labelled synthetic/injected; they are not live evidence. Both use
only a loopback fake provider, disposable homes and the unchanged reviewed native
package. No live credential/host, download, paid service or Action is involved.
