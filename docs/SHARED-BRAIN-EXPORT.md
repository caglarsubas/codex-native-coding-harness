# Exact single-brain export from shared Codex home

`shared_codex_exact_brain_export_v1` is an explicit operator read-only collector
for one existing registered brain on its unchanged reviewed original host. It
fixes the private-source-home restriction without making a shared home private,
copying that home, editing native stores or expanding native execution authority.

## Closed source

The authenticated native initialization must name the current OS user's literal,
canonical `~/.codex`. The ledger/catalog/original binding must still identify one
exact brain, workspace, checkout and both native project IDs. Require the sole
completed receipted original Play, its exact closed owned observer and latest
ended turn, an empty unowned paused schema-v4 standard run, no pending control,
Brain Stop, runner, worker, merge or strict enrollment. Expiry is preserved; an
expired phase does not gain permission to execute through an export.

The collector allows only initialization and fixed `project/read` and
`thread/read(includeTurns=true)` for those exact IDs. It never lists projects,
threads or directory contents. It reads only the `rollout-...-BRAIN_UUID.jsonl`
path returned by that exact native thread under the same shared home's sessions.
It opens no auth/config/plugin/native database/sibling conversation files and
never follows a symlink, hard-link alias, writable ancestor or foreign owner.
Directory descriptors and repeated file/chain checks fence path substitution;
the source file's full epoch/bytes are pinned. Unrelated sibling writes do not
renew or invalidate a brain's evidence merely by changing directory timestamps.
No source permissions are changed: owner-controlled 0755 directories and 0644
JSONL are accepted only on this exact, separately named shared export path.

The same complete root-history gates apply: bounded 16MB/100,000-record JSONL,
exact brain/cwd, one root session, complete contiguous zero-based pagination when
present, and no foreign/base-linked/fork/goal/dynamic-tool/plugin/capability roots.
Unsupported, malformed, partial or changing source remains unknown. Nothing is
converted, stripped or reconstructed to manufacture a supported history.

## Private retention, not native transfer

Use explicit registered platform/workspace routing:

```text
standard-public-brain-export ORIGINAL_BINDING NEW_PRIVATE_DIRECTORY
standard-public-brain-export-status PRIVATE_DIRECTORY
```

The new directory's existing parent must be owner-private; the export must be
disjoint from the shared home, checkout and live ledger/registry. Collection
repeats actual source metadata/bytes before retention and afterward. It publishes
only a complete private 0400 `history.jsonl`, a 0600 context/identity/hash manifest
and intent beneath a 0700 directory. The archive contains that one brain's
conversation and stays private: never commit, print or send it to inference.
No credential or native database is copied. Original Play/run/receipt/usage/gap/
expiry bytes and file identities remain unchanged.

Interrupted retention stays `partial_export_unknown`. The directory is never
overwritten or silently retried. Status reads private files only, retains the
original collection time and grants no new source freshness, terminal safety,
cleanup, policy verification or pilot acceptance. Normal polls and Help invoke
neither collector nor native writes.

## Opt-in use by exact identity transfer

The existing private-source v1 transfer is unchanged and still refuses shared
homes. A future separate owner-reviewed transfer can explicitly opt into the
retained shared export:

```text
standard-public-transfer-prepare ORIGINAL_BINDING REVIEWED_DESTINATION_BINDING NEW_PRIVATE_DIRECTORY --source-export PRIVATE_EXPORT/export.json
```

Only this new version-2 private transfer specification pins the export manifest
and archive epochs/hashes alongside the existing original-run context. At every
existing native claim boundary it rereads the original host/file and requires
complete agreement with the private export. A forged, stale, edited, cross-brain
or cross-run archive is no substitute for current source evidence. Reading time
alone does not expire review, but drift invalidates it. Existing original-run/Play
permanent fences and separate restore/load/membership claims remain mandatory;
another export or review directory never enables native replay.

Export itself authorizes no destination connection, inspection load, project
restore, assignment, new host, dashboard cutover or native permission response.
Those actions retain their exact owner review and independently qualified host
prerequisites under PUBLIC-IDENTITY-TRANSFER.md. Transfer remains metadata-only,
not historical cleanup, old-policy backfill, checkpoint/receipt fabrication,
same-run transition, Play/recovery/Resume or acceptance. Source merge and dashboard
installation remain separate. The already expired pilot is not reopened.
