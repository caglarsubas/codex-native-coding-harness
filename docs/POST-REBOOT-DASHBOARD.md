# Certificate-aware read-only recovery workspace

`post_reboot_dashboard_v1` is a separate operator path for the exact completed
[maintenance certificate](POST-REBOOT-MAINTENANCE.md) and actually issued
[post-reboot host repair](POST-REBOOT-HOST-REPAIR.md). It restores an authenticated,
selected-project graph/inspector view **without** changing ordinary identity
validation or operational authority. It is not the normal dashboard's `serve`
route with a substituted Registry, monkey-patched identity or writable ledger.

Revalidate the full completed certificate and original sealed preparation,
database schema/contents/inodes, original requests, receipts, usage/gaps/clocks,
repository identity and holds. Keep the old device pins and all original binding
bytes intact. Historical device comparison remains confined to that certificate;
every current socket, package, process and output pin uses its actual epoch.

Accept only the complete issued canonical post-reboot repair. Hash the exact
qualified PR-193 launch source as inert bytes (or the identical current source
for a newly reviewed launch); never import historical Python. Revalidate its
original launch/package/home relationship, permanent intent/empty exec claim,
issued status and live PID/birth/argv/checkout. Repeat original-PID absence and
require the exact new canonical physical socket to be owned by that process.
The advertised symlink is not a bound endpoint. Never connect, recreate, unlink
or adopt the retired socket, signal a PID or launch/restart a host.

Verify the non-credential home backup, original configuration and retained
history prefix. `auth.json` is inspected only by metadata: no open/hash/copy,
sign-in, refresh, replacement or native SQL. Unknown or changing state refuses.

## Explicit inspection, then file-only review

Use a qualified source after its separate manual merge and inactive installation:

```text
python3 -B -m orchestrator.post_reboot_dashboard inspect REPAIR_JSON ORIGINAL_LAUNCHED_SOURCE FRESH_APP_CATALOG_JSON NEW_EVIDENCE_DIRECTORY
python3 -B -m orchestrator.post_reboot_dashboard prepare REPAIR_JSON ORIGINAL_LAUNCHED_SOURCE EVIDENCE_DIRECTORY NEW_PRIVATE_VIEW_DIRECTORY --port 8810
```

The catalog input is the actual complete `codex_app.list_projects` result, with
the following wrapper; it is not inferred from a directory or a project label:

```json
{"source":"codex_app.list_projects","observedAt":1790000000,"completeResult":{"schemaVersion":2,"projects":[]}}
```

Require one exact local checkout match and its separately pinned app catalog ID.
The owned project ID remains distinct. Inspection requires a fresh catalog
observation, the exact new private endpoint and matching initialization identity.
The existing closed `RestartReadProxy` repeats only project/brain metadata,
latest ended-turn metadata, complete empty MCP inventory, effective policy and
non-refreshing account metadata. No schema export, native load, subscription,
turn, permission response, cancel, discovery or provider request is added.
Raw prompts, command bodies, account identity/routing and credentials are not
retained. Account-present is not token freshness, model access or entitlement.

An unloaded brain may be viewed; its null policy and current terminal coverage
remain unknown. Viewing it must not create a reason to reload. Inspection saves
new private intent/result and a single-brain candidate binding. This is not an
operational binding cutover or a native receipt. Partial inspection stays partial;
there is no automatic recollection, fallback or repair of its result.

`prepare` is file-only. Retain its `request` as the private review JSON. It pins
the full current certificate/context, issued host/socket, original and proposed
bindings, app-catalog/native observations, Python **and** closed frontend bytes,
port, disjoint private browser-store directory and permanent startup owner.
Review validity is `scope_changes`, not a short reading countdown. Changing
source, assets, scope, account/routing, native activity or policy invalidates it.
The old blocked ad-hoc candidate assessment is not executable approval for this
new supported control. No source installation or generic assent confirms it.

## Verified backup and one foreground startup

```text
python3 -B -m orchestrator.post_reboot_dashboard backup PRIVATE_REVIEW_JSON NEW_PRIVATE_BACKUP --writers-stopped
python3 -B -m orchestrator.post_reboot_dashboard serve PRIVATE_REVIEW_JSON VERIFIED_PRIVATE_BACKUP --writers-stopped --catalog FRESH_APP_CATALOG_JSON --confirm-hash EXACT_NEW_REVIEW_HASH
```

Require independently stopped older database writers, repeated fixed handle
checks and a free exact reviewed loopback port. Never stop an unknown port owner.
Back up **all** registered databases as verified self-contained SQLite copies,
plus every explicit historical/certificate/launch/evidence/binding input. Require
private disjoint files, exact complete inventory and unchanged originals.
Native credentials and stores are not copied by this dashboard backup; the
separately verified original non-credential native-home backup remains intact.

One exact new owner confirmation commits the canonical external startup owner
and serve claim **before** another full context check, fixed startup metadata
inspection and HTTP bind. The owner is workspace/original ledger inode/startup,
not source, request ID, port, PID candidate or view directory. Failed, partial,
interrupted or unknown startup is permanently consumed; another directory or
new source cannot retry it. No automatic/detached supervisor, reconnect owner,
keeper, model heartbeat or host-lifetime guarantee exists. A later genuine
dashboard exit needs a future separate contract, not reuse of this approval.

The server binds `127.0.0.1` only. Its private session link and existing browser
pairing implementation use **only the new reviewed private view directory**;
old dashboard-session/auth stores and all operational stores remain unchanged.
Only local login/logout/remember-browser operations can POST. All operational
POSTs, PUT/PATCH/DELETE and unsupported methods are refused before operational
handlers. Host/Origin checks, private HttpOnly/SameSite cookies, no-store,
frame/CSP protections, closed static assets and a bounded request timeout apply.

## Same-page view, not a dispatcher

The same warm-paper/forest-green visual language, graph pillar and contextual
inspector are used at desktop and 320px widths. Selecting the brain or retained
preparation is local navigation, not a chat send or native request. The view
shows the original unqualified readiness ID, separate ended preparation, honest
usage/reservation/overrun/gaps and the missing next gate. There is no chat sender,
Play, readiness, Resume, cancellation or approval control in this recovery mode.

HTTP refresh revalidates the certificate/source/host/file scope but uses the
**original startup observation timestamps**. It never opens a native connection,
repeats account reads, acquires a controller or renews evidence. The saved native
observation becomes visibly stale after the existing five-minute diagnostic
window. Current policy verification is always false; even a matching saved
loaded-default report is historical, not execution/safety authority. Scope/source
loss returns unavailable and hides the last good view, with no stale fallback.
Foreign workspace routes, traversal, extra query parameters and unknown APIs
cannot expose another project or invoke ordinary controls.

Original requests, runs, claims, usage and bindings stay unchanged. This provides
neither worker readiness nor a new phase, reload, old readiness/Play/recovery
replay, usage reset, ownership release, terminal cleanup or pilot acceptance.
Current and historical terminal safety remain unknown. Ordinary Registry/Ledger,
normal dashboard and effect gates remain strict and unmodified.
