# Quarantine an unqualified attempt without rewriting its history

`standard_quarantine_v1` is an operator-only owner disposition, not terminal
settlement, a safe checkpoint, successful closeout or permission to continue.
It addresses an expired, empty, unowned paused standard attempt whose missing
historical safety evidence cannot be recovered. It does not fabricate the
Pause/recovery sequence required by older closeout adapters.

## Exact local review

Use explicit platform and workspace routing with the installed helper:

```text
standard-quarantine-preview
standard-quarantine-confirm PRIVATE_REVIEW --confirm-hash EXACT_REVIEW_HASH
standard-quarantine-status
```

The preview returns `request` and its exact `reviewHash`. The owner/operator
stores that request in a canonical, owner-only regular file and confirms only
that displayed hash. Models/brains must not self-confirm it. This is a local
operator interface, not an assistant, HTTP, inference or native approval route.
Review lasts until scope changes, not an arbitrary countdown. Reading, polling
and installation do not prepare or confirm a disposition.

Before application, separately quiesce all older ledger writers and retain a
verified private state backup. This source grants no live installation or
application. A source merge is not an exact disposition confirmation.

## Narrow eligibility

Only an expired schema-v4 `standard_cooperative_v1` run qualifies. It must be
paused with no controller/private controller credential, runner, admission or
Brain Stop; no tasks, merges, legacy workers/queue, open decisions or pending
commands/uncertain notifications may remain. Require one completed, accepted,
receipted original owned Play, its exact ended turn and closed observer, and no
approval intents or observed descendants. Unknown delivery is never absence.
Strict Harness, maintenance and public-task schema-v5 runs refuse this version.

Pin complete old meta/run, commands, repository records, decisions and
continuations; original capture hash, private ledger/registry file identities,
retained catalog mapping and both native project IDs are included. Read the
original binding as private bytes only; never validate/connect its old endpoint.
The original scope and restricted policy are preserved, not retrospectively
verified. Revalidate the entire review under registry then ledger locks. A
changed usage sample, source, identity, receipt or original file invalidates it.
Conflicting registered foreign tasks/merges/workers refuse application.

## Permanent disposition and interruption

The exclusive, flushed private `standard-quarantine.json` claim precedes local
commit. One immutable hash-addressed snapshot retains the reviewed original
state, outcome `quarantined_unqualified`, exact review and original recording
time. Only meta's schema marker, disposition pointer and revision change; the
old run and command values remain identical, including checkpoint, consumed
effects, missing evidence, observed usage/high-water and expiry.

Schema-v6 metadata requires `quarantineLedgerVersion: 1` and its disposition
hash. Older helpers refuse the schema; this source refuses every normal ledger
write if either the file or meta marker exists. Deleting/damaging one marker
cannot remove the other fence. No downgrade/mixed-running-writer guarantee is
claimed: quiescing older processes is mandatory before rollout.

A lost response returns the exact validated original local receipt. It never
reapplies the disposition, refreshes time or sends a native action. A file claim
without its matching database commit remains `quarantine_incomplete_or_changed`:
no automatic retry, deletion, ownership release or unfence exists. Invalid saved
history is unavailable and blocked, never silently reconstructed.

## What remains held

Quarantine is **not** evidence that processes stopped. Current and historical
terminal safety remain unknown. It releases no controller/resource, reconciles
no historical effect, clears no old policy guard and does not extend the old
phase. The recorded repository identities remain held across standard claim and
public native creation/first-turn checks in the same registered platform. An
uncheckable foreign disposition refuses rather than counting as free capacity.
No global/unmanaged-process exclusion or OS attestation is claimed.

The graph and inspector display **Quarantined · unqualified**, preserved usage,
unknown safety and the repository hold. Brain history/drafts remain readable;
the composer cannot send. No recovery, Resume or Play CTA is offered for this
attempt. Status projections collect no native evidence and grant no authority.

This version does **not** allow a successor on the held repository, load the old
brain, change its binding or activate a new run. Future separately scoped work
still needs its own reviewed authority, non-conflicting resources and qualified
current evidence. It cannot reset or hide this attempt's usage. A separate
successor protocol is required where those conditions cannot be established.

See [prospective capture](PROSPECTIVE-LIFECYCLE.md). Neither that new capture nor
a fixture pass can supply missing historical process facts for this old attempt.
