# Ended-Pause receipt/checkpoint recovery

This separately signed, one-shot standard-project control repairs one ledger
gap: the exact Pause was delivered to the reviewed owned host, its turn completed
and its observer closed, but no Pause receipt or checkpoint was retained. It does
**not** replay Pause, Play or any diagnostic. Strict Harness, pre-turn failed-Pause
recovery and conversation-reply recovery remain separate.

## Owner review and scope

The workspace offers **Review Pause receipt recovery**. Opening that review reads
only project, brain, latest-turn and, when loaded, current tracked-terminal
metadata. It cannot start, resume or interrupt a native thread. The signed preview
pins the original Pause fingerprint and notification, run, phase, known usage,
coverage gaps, original expiry, brain and unchanged host binding. Both retained
project identities must match the registered checkout independently.

Confirmation uses the existing authenticated, session/revision-bound assistant
adapter: type **confirm pause receipt recovery** for that displayed preview or use
its confirmation button. Vague assent and model text cannot confirm it. Review
expiry remains five minutes; refreshing an unconfirmed review sends nothing.
After confirmation there is one hour to receive the exact recovery, not a renewed
phase duration. A failed or expired attempt cannot obtain another wake.

Eligibility requires an empty stopping cooperative standard run, dispatch paused,
released controller, no tasks, packets, workers, runner, merge, enrollment,
admission ownership, pending decision, other pending request, Brain Stop or brain
replacement. The original notification must have an acknowledged `owned_turn_start`,
exact completed turn, closed observer and pinned restricted resume profile. Any
native approval record fences this path. Unknown delivery or a still-active turn
cannot use it. A prior preparation or failed-Pause recovery cannot migrate here.

## Native inspection and the one-shot boundary

An unloaded thread has **unknown** terminals, never zero. It may appear in the
review only when repeated metadata reads agree on the exact completed Pause turn.
The confirmed recovery authorizes one claimed metadata-only `thread/resume` on
that same host, with `workspace-write`, `on-request`, Code Mode disabled and
`excludeTurns`. This loads for inspection; it is not phase Resume and grants no
dispatch authority.

Before `turn/start`, repeated independent project/brain/latest-turn reads must
still agree with the reviewed identities and completed turn. The loaded brain
must be idle and its current tracked-terminal list known, empty and fully
paginated. A changed turn, active thread, unsupported/missing tracker, terminal,
new Stop, changed run/usage/expiry or pending ownership refuses turn start. The
loaded inspection is retained under the **new** recovery notification, not the
original Pause. Current-host empty terminals do not prove historical cleanup,
all descendants or the outcome of an earlier diagnostic.

The existing notifier commits its durable claim before connecting. Failed load,
uncertain response or failed turn start consumes the recovery slot permanently.
Reads, expired reviews, HTTP replay and restart never send again. There is no
replacement, automatic retry, host fallback, rebinding or new dispatcher.

## Designated brain procedure

Read this document and the source orchestration skill completely. Use the exact
source checkout, registered platform and workspace from the fixed notification.
Verify this task is the designated brain. Read its inbox and `standard-state`,
then acquire only its normal controller. Do not use generic `process`/`receive`,
drain saved messages, execute the old instruction or respond to native prompts.

1. Use `standard-brain` with JSON operation `pause_receipt_recovery_receive`, the
   exact `runId` and recovery `requestId`. It validates the permit and committed
   loaded-idle inspection before recording the original Pause receipt. The old
   notification stays unchanged.
2. Retain only an empty checkpoint: operation `checkpoint`, same `runId`,
   `outcome: "paused"`, a bounded factual summary, `brainObservedTokens: null`.
   Use observed `duration`/`usage_evidence` reasons where applicable. Null means
   no new measurement; every known counter/high-water and existing gap remains.
3. Release the controller with that checkpoint, then end the turn.

The 500,000-token allowance is cooperative guidance for this single receipt turn,
not a provider cap, phase-budget increase or permission to continue an expired
phase. No task creation/continuation, source/settings changes, merge, mission
review, Play, phase Resume, diagnostic, task terminal execution or native approval
response is permitted. A receipt and checkpoint are not effect reconciliation,
terminal settlement, successful completion or pilot acceptance. The checkpoint
retains `effectOutcome: unknown`, `historicalTerminalCoverage: unknown` and
`taskTreeComplete: false` explicitly.
