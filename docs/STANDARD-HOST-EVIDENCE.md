# Current standard-brain host evidence

## Problem and source fix

An owned Play could be delivered, receipted and safely paused because the
designated brain had no supported pointer to the operator-reviewed host binding.
The dashboard knew the binding, but its fixed standard notification supplied
only source, registry and workspace. Asking the owner for that private path
repeated the orchestration burden the dashboard is supposed to remove.

For a future notification in an existing standard run, the same durable
one-shot claim now retains a hash-addressed, owner-only copy of the trusted
startup binding in that ledger. It never discovers a socket, changes/reviews a
binding, copies credentials into a browser projection or adds a send path. A
changed/insecure existing copy refuses before delivery; it is never overwritten.
The standard fixed pointer names its exact command and run, and directs the
brain to `standard-host-inspect`. Browser message text cannot choose a file,
host, method, target or policy. Duplicate notification requests do not recollect,
rewrite the private copy or send again. Existing historical notifications are
not upgraded, reissued or given fabricated host observations.

## Explicit read-only inspection

Only the current designated-brain controller in an exact registered cooperative
run can call:

```sh
python3 -m orchestrator.cli --platform REGISTRY --workspace ID \
  standard-host-inspect RUN_ID COMMAND_ID
```

The command requires the latest owned standard control for this brain, exact
notification-bound run (and run payload where present), accepted
`owned_turn_start`, confirmed turn ID and still-open
owned subscription. Before any host/file read it enforces the standard/strict,
controller, registry and legacy ownership fences. It verifies the private
handoff hash and endpoint executable/socket/initialization pins, separately
retained app-catalog and owned app-server project IDs, exact native project root
and brain checkout. It makes two bounded `project/read` and metadata-only
`thread/read` samples, requiring unchanged active brain identity, then rechecks
the binding, catalog, ledger revision, run and approval context after I/O.
Missing native active flags or waiting-on-approval/user-input flags are explicit
issues, not an empty pending-approval inventory. The retained resume profile is
bound to this exact command and confirmed turn, not merely the same brain.
No thread listing, native resume/start, approval response, discovery, source
execution, token collection, ledger write or ownership release is permitted.
Each explicit invocation has its own real observation time; reads never rewrite
the original resume receipt or renew reviewed authority.

The host profile is retained from the *existing successful* metadata-only
`thread/resume` response before its `turn/start`. Only closed fields are retained:
binding hash, brain ID, original time, exact requested policy, successful resume
acknowledgement, and reported sandbox type/approval policy/reviewer. Private
conversation, model, writable roots, endpoint and arbitrary native error payloads
are excluded. Missing or unfamiliar fields are null, not inferred from requests.
Code Mode's disabled configuration is acknowledged by successful resume but is
not independently reported by this installed protocol. Named-profile provenance,
complete effective sandbox roots and OS enforcement are not attested here.

The result labels these facts separately, exposes unknown coverage and reports
known contrary/missing policy or unresolved recorded approval as `issues`.
Even a report with no issues is **not** execution/approval authority, a complete
native-effect inventory or pilot acceptance. The brain must honor the reviewed
mission, explicit gaps, current tool metadata, fresh usage and Pause at each
effect boundary. Unknown global/descendant coverage cannot be converted to none.
Permission-denial pilots still require the exact owner decline and witnessed
denied/not-executed result; this inspection cannot synthesize either.

## Rollout and continuation

Source, manual PR merge, installation and live qualification remain separate.
Quiesce older writers and back up the private ledger/registry before installing
compatible source. Do not backfill a stopped turn's profile, modify its receipt,
delete uncertainty, rebind a host, extend a run or replay Play during rollout.
A paused phase keeps its original usage, gaps, scope and expiry. Its existing
signed Resume must be separately owner-confirmed after readiness/usage checks;
the resulting one-shot owned notification carries the new handoff. An expired
or otherwise inadmissible Resume stays fenced and needs its normal next-step
control, not an invented continuation exception.
