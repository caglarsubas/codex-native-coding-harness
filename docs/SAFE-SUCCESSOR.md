# Disjoint standard successor — source contract

`standard_successor_v1` records separately reviewed lineage from an already
quarantined attempt to an **existing**, independently scoped standard project.
It never reopens the old run. It is not historical cleanup, a closeout, a retry,
a new native identity, a binding change or pilot acceptance.

This delivery is source and disposable qualification only. It installs nothing,
confirms no owner control and changes no running dashboard or paused pilot.

## Why a separate target

An expired attempt with unknown historical effects cannot safely become its own
new phase simply by changing a phase ID or giving it another allowance.
[Quarantine](QUARANTINE-DISPOSITION.md) preserves the entire old ledger and keeps
its repository ownership. A clone, linked worktree, nested checkout or another
path to the same remote is not a disjoint resource. Unknown identity is not free
capacity, and current empty trackers never prove historical cleanup.

The source must already have its exact valid owner-confirmed quarantine receipt,
schema-v6 marker and unchanged old state. This adapter cannot confirm quarantine
or silently substitute for its owner review. The source remains read-only.

The target must already be registered in the same private registry, with a
different brain and canonical ledger identity, an empty paused schema-v1
pre-phase ledger, no controller credential/runner/tasks/commands/queue/decisions/
continuations, no Brain Stop and no strict enrollment or admission binding.
Its exact standard phase-delegated mission must already have its own owner
review. A consumed/uncertain attempt cannot be relabelled as this target.

By default both repositories need independently observed canonical Git common-directory
and conventional normalized origin identity. Reject common roots, ancestry,
linked worktrees and equal remotes. Recheck other registered held/active scopes
at admission, native control delivery, worker claim/issue and public task
creation/first-turn boundaries. This is bounded registered ownership accounting,
not proof that unmanaged processes or global provider capacity are free.

### Explicit local-only identity review

An owner preparing this exact successor may explicitly select
`standard-successor-preview TARGET BINDING --local-only`. The returned immutable
request includes `identityPolicy: reviewed_local_git_v1` and each complete local
proof. This is another exact until-scope-changes owner review, not a global
fallback from missing/invalid origin and not an automatically applied policy.
Without the flag, the conventional-origin gate is unchanged.

The scoped observer requires a standalone canonical Git root, unchanged private
local config/file epoch, known complete SHA-1 history and repeated bounded root
commit sets. It verifies **absence of every remote**, rather than translating a
missing origin into an invented remote or zero ownership. Shared history roots
conflict across copies, clones, removed origins and forks even when inode/path
identities differ. A conventional-origin foreign owner is also compared by its
complete history, not only its URL. Nested/linked worktrees, symlink/config aliases,
additional worktrees, shallow/partial or alternate object sources, grafts, replace
refs, residual remote references and unsupported configuration refuse. Bounds,
errors or drift remain unknown, never free capacity.

The proof intentionally does not permanently pin target HEAD: separately scoped
producer commits may advance it without changing its repository lineage. Exact
task base/commit checks remain separate. New unrelated roots, configuration or
remote changes invalidate the retained review at admission and every existing
successor effect boundary. The helper's own source hash is included in the
successor source pin. Ordinary resource audits still report absent origin as
unknown; no legacy, Harness, global or unmanaged exclusion claim is widened.

This review writes no repository metadata and releases no predecessor ownership.
Quarantine, mission review, binding and fresh Play remain separate controls.

The target's existing private reviewed binding must already name only that brain,
exact app-catalog and native project IDs, registered checkout and pinned endpoint.
Require `workspace-write`, `on-request`, user approvals and Code Mode off, plus
the separately reviewed `loaded_thread_policy_v1` native evidence contract.
No binding file, native project, brain, host, trust entry or credential is made
or changed by admission. The public worker backend remains opt-in; it must
already be present in the reviewed binding to use that transport.

## Operator review and durable admission

Use exact registered routing from the compatible source checkout:

```text
python3 -m orchestrator.cli --platform PRIVATE_REGISTRY --workspace OLD_WORKSPACE standard-successor-preview TARGET_WORKSPACE PRIVATE_EXISTING_TARGET_BINDING
python3 -m orchestrator.cli --platform PRIVATE_REGISTRY --workspace OLD_WORKSPACE standard-successor-confirm PRIVATE_REQUEST --confirm-hash EXACT_REVIEW_HASH
python3 -m orchestrator.cli --platform PRIVATE_REGISTRY --workspace TARGET_WORKSPACE standard-successor-status
```

The preview is file/local-state only. Retain its **request object**, not the
wrapper, in a new bounded owner-private JSON file. The owner must review that
exact request/hash; the model or designated brain cannot self-confirm it.
There is no timer expiry: unchanged scope remains reviewable, but every pin is
revalidated before application. No old approval applies to a new target/scope.

The request pins source module hash, old quarantine receipt/file/DB identities,
original run and usage/report/expiry, target DB/registry/repository identities,
both native project identities, mission review, complete current target metadata
and existing binding bytes/file epoch. It explicitly denies release, cleanup,
terminal safety, binding/native changes, Play and acceptance authority.

Under registry-then-target locks, confirmation revalidates the whole request,
fsyncs an exclusive target `standard-successor.json`, then an exclusive outgoing
source-lineage claim in the registry, and commits one target snapshot/schema-v7
receipt. It writes **no byte in the source ledger**. The outgoing registry claim
prevents multiple successors from the same quarantined attempt; one target has
one admitted lineage and one fresh Play. Exact receipt rereads do not repeat it.

Partial claims fence the target permanently; there is no retry, automatic repair,
claim deletion or implied rollback of an uncertain cross-file transaction.
Missing/corrupt markers, source/target/binding/mission/routing drift and source
module changes fail closed. Keep the complete private state for investigation.
Do not describe an interrupted admission as accepted or reconstruct its receipt.

The separately reviewed [partial-admission disposition](PARTIAL-ADMISSION-DISPOSITION.md)
may record an unchanged uncommitted attempt as unqualified while preserving both
claims and every database. It does not complete admission, unfreeze the target,
remove the source's outgoing claim or grant a new successor/Play. Installing the
registry-size validation repair never applies that disposition or retries a claim.

Schema-v7 support does not make older running writers safe. Before separately
authorized live admission, quiesce **all** writers, preserve verified private
backups of both ledgers/registry/sidecars and confirm every launcher uses the
compatible source. Older helpers refuse v7 at open; mixed already-running writers
and downgrade/partial-claim recovery are not qualified.

## Fresh Play, not replay

Admission records lineage only. It neither reviews a mission nor starts work.
The target still needs a separate signed owner Play, bound to its exact reviewed
mission and this lineage hash. The signed preview includes the predecessor's
observed usage/high-water/coverage and explicit unknown terminal safety.

The new target run has a new ID, clock and reviewed allowance for its own work.
These are **new authority over different resources**, not an extension, reset or
replacement of the original run. Old usage, gaps, expiry, Play/Pause/recovery
claims, observer evidence and held resources remain immutable. Do not subtract
old usage, mark its gaps complete, infer a remaining global/account budget, or
report the target's initial `not_observed` counters as evidence of no usage.
The normal fresh measurement, budget, model, capacity and checkpoint gates apply.

The target dashboard displays preserved lineage and prior usage separately from
its run. Rendering/polling submits nothing. No advisory inference output may
confirm admission or Play. Strict Harness is unchanged.

## Already-loaded-only native delivery

For this lineage, a newly committed target Play/Pause/Resume control uses the
same durable one-shot notification claim but **never calls `thread/resume`**.
Ordinary messages, recovery, metadata loads, observer adoption/reconnect and
fallback to the historical endpoint cannot use this path.

Before the native turn boundary, repeat exact project and brain metadata reads,
complete bounded current tracked-terminal pagination, and independent effective
loaded-policy reads on the already reviewed target host. Require loaded idle,
no active flags or current tracked terminals, unchanged identity/scope, matching
restricted native policy and a still-permitted local control/expiry. The public
protocol's closed `{"type":"idle"}` enum is supported explicitly; a malformed
flag field, active/approval wait, missing/unsupported tracker or `notLoaded`
refuses without a load. Authentication uses the existing non-refreshing guard
when the reviewed public-task backend requires it.

Retain `nativeLoadedProfile` using `successor_loaded_only_v1`, then independently
reported policy evidence, then recheck before the original observation/capture
boundary and one fresh `turn/start`. Native calls and ledger state are not an
atomic transaction: Pause remains cooperative, and ambiguous delivery consumes
the request and retains ownership; never retry it. No historical safety follows
from a current idle observation. Prospective item lifecycle capture remains
original-bound under [PROSPECTIVE-LIFECYCLE.md](PROSPECTIVE-LIFECYCLE.md).

The explicit controller-bound `standard-host-inspect` broker returns **version 2**
with `loadedProfile` for this control. It must not fabricate `resumeProfile` or
set `resumeAcknowledged`. Independent policy evidence still gates worker effects;
reported configuration alone is insufficient. Older version-1 turns and reports
are unchanged. The existing foreground observer serves an explicit request; no
protected socket is granted to the sandbox and no idle collector is added.

The native protocol distinguishes metadata reads, thread loading and turn start;
see the [official app-server protocol guide](https://learn.chatgpt.com/docs/app-server).
The independently reported policy method remains the explicitly reviewed native
extension described in [NATIVE-POLICY-EVIDENCE-ADAPTER.md](NATIVE-POLICY-EVIDENCE-ADAPTER.md),
not an inferred stock-server capability or OS/active-step enforcement attestation.

## Qualification and current pilot boundary

`tests/test_standard_successor.py` exercises local admission, separate fresh
Play, loaded-only send, version-2 broker inspection, task result and checkpoint in
disposable ledgers with synthetic native responses. Adversarial cases include
shared/unknown scope, late foreign ownership, hardlinks, partial claims, changed
binding, deleted marker, downgrade, Pause races, expiry, unloaded/malformed policy
and incomplete current terminals. Every journey checks the source DB fingerprint.

The compiled fixture adds `--loaded-only-preflight` to
`scripts/qualify_public_native_tasks.py`. It uses a temporary native home/project/
thread and loopback fake provider. After its one bounded disposable turn, it
repeats real loaded-idle/policy/terminal metadata reads, with **zero resumes**.
This separately qualifies the real wire shape, not live target admission or the
complete source journey against a real model. Optional tool/lifecycle exercises
remain disposable; OS cleanup, live migration and pilot acceptance stay false.

A live old run without confirmed quarantine cannot enter this path. A portfolio
without an existing disjoint, reviewed target cannot enter it either. An unloaded
target stays blocked under the no-reload constraint. Do not create/register/bind
one, apply quarantine, confirm admission, wake a brain or replay an old control
merely because this source ships. Report that exact missing prerequisite instead
of claiming that the original pilot ran, completed or became safe.
