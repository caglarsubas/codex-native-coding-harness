# Ended recovery: continuation proposal, not authority

**Status: proposed policy only. No executable adapter, wake or live installation.**

The [ended-Pause receipt recovery](ENDED-PAUSE-RECEIPT-RECOVERY.md) is permanently
one-shot. An accepted completed turn without a ledger receipt is not a failed
pre-turn send. Runtime repair, a new host, a different command name or a new
signature cannot make resending it safe or permitted. The existing permit,
notification, observer, usage, expiry and original Pause must remain intact.
The orphaned-turn replacement-host exception recovers a controller only; it
cannot migrate this claimed recovery or authorize another receipt-only turn.

## Proposed path without another wake

The candidate successor is **owner reconciliation of an exhausted recovery**,
not another brain recovery attempt. A future separately reviewed adapter would:

1. Pin the exact original Pause, exhausted recovery command/native turn/closed
   observer, run/phase, both project IDs, brain, checkout and native policy.
   Preserve their complete private byte/hash records, usage/gaps and original
   expiry. Do not reclassify an accepted turn as unsent or delete its permit.
2. Require separately reviewed runtime repair, host launch/retirement and binding
   continuity first. A metadata-only inspection load, if needed, needs its own
   explicit authority; an unloaded brain is unknown and is never resumed merely
   to manufacture idle/terminal evidence. No preview or polling collects it.
3. Repeatedly observe that same completed turn, current loaded-idle state and
   known-empty current tracked terminals on the reviewed host. Match exact
   catalog/native project identities and checkout, not names. Missing, truncated,
   stale or changing metadata, a later turn, pending native decision, abandoned
   controller, workers, queue, runner or uncertain effect retains the refusal.
4. Reconcile historical native effect/terminal and permission-decision evidence
   separately. Current empty terminals cannot prove an old diagnostic was denied,
   never ran or cleaned up. Absent evidence remains unresolved. No diagnostic,
   Play, cancellation, approval response or command is replayed to obtain proof.
5. Record a new owner-only **blocked/unqualified reconciliation record** with its
   own exact signed scope and durable idempotent receipt. It does not impersonate
   a brain receipt, add a safe checkpoint, overwrite either original command or
   turn, release native effects or mark pilot success. Do not reuse `phase_close`,
   which still requires its existing recovery receipt/reply prerequisites.
6. Only after independently reconciled evidence permits terminal closeout may a
   separately reviewed closeout end this run as blocked/unqualified. A successor
   remains a new mission with separate Review and Play and fresh usage/capability
   evidence. Neither a reconciliation record nor closure passes the pilot.

This proposal deliberately contains **no second native turn**. It does not
authorize any of these steps, extend an old approval or relax strict Harness.
If historical effects cannot be reconciled, the truthful outcome is an
unqualified, still-fenced pilot, not an automatic fresh attempt. A proposed new
brain wake would be a material change to the one-shot policy, requiring its own
explicit owner policy decision rather than being hidden inside runtime repair.

## Required future verification

Before implementation/live qualification, review the exact closed schemas and
authority boundary; test immutable original records, unknown/unloaded terminals,
both project IDs, host continuity, controller/approval ownership, historical
effect gaps, changed latest turns, usage/expiry preservation, Pause races,
duplicate confirmation, interrupted local receipt retention and project/session
isolation. Source delivery adds no live route for this proposal. Runtime and
pilot acceptance require independent evidence, not fixture assertions.
