# Worker-phase evidence after preparation

`post_startup_worker_readiness_v1` is an explicit metadata-only evidence path,
not a replay of readiness and not a phase-control notification. It sends no
brain instruction and constructs no old or new catalog receipt. The completed
preparation's proposal remains inert. All original rows, runs, requests, claims,
usage/gaps/clocks, repository holds and bindings remain unchanged. Normal
writes remain fenced. Source delivery and disposable qualification install or
activate nothing; manual merge, safe installation, live observation, exact
worker-phase review/Play and actual pilot acceptance are separate.

## Supported predecessor

Require the exact canonical positively completed preparation described in
[the startup contract](PRESTART-STARTUP-PREPARATION.md), including a budget
checkpoint with a positive new receipt. Validate both local markers, external
intent and full closed journal, original mailbox publication/receipt agreement,
actual original load/turn claims and closed observer, all registered database
identities/logical contents, unchanged repository/mission/admission/binding and
the original readiness's positive pre-load diagnostic. Unknown, interrupted,
partial, stopped, changed or unlisted records refuse; they cannot gain another
load or turn through this path.

Supply the original startup execution package explicitly. Current-source
fixtures must match the complete original source proof; historical PR-189 is
accepted only at its exact allowlisted implementation hash, path and epochs.
Historical Python is hashed, never imported or executed. Compare the proved
implementation difference separately; do not rewrite original hashes or
timestamps. Existing historical admission and original readiness source proofs
remain mandatory. Source continuity is not freshness or an execution permit.

## Explicit collection and inspection

```text
python3 -B -m orchestrator.worker_readiness --platform PLATFORM --workspace TARGET collect EXACT_ORIGINAL_STARTUP_SOURCE NEW_PRIVATE_EVIDENCE_DIR
python3 -B -m orchestrator.worker_readiness --platform PLATFORM --workspace TARGET status PRIVATE_EVIDENCE_DIR
```

Collection creates one new disjoint private artifact directory. It opens the
unchanged bound host through the existing read-only proxy, never an old endpoint
or a replacement. The closed RPC vocabulary permits only metadata: exact
project/brain/latest-ended-turn, actual effective policy and current trackers,
complete empty MCP inventory, non-refreshing account reads and two complete
agreeing model-page sets. Validate the pinned binary's exported task schemas in
an isolated empty credential-free home before connecting. That fixed schema
export starts no server or model. Verify original context and endpoint before
and after I/O, and retain the earliest native observation time with the existing
120-second freshness bound. A status read cannot collect, export, reconnect or
renew this time. Failed/partial artifacts stay unknown and are never overwritten
or automatically recollected. Another explicit metadata observation is not a
retry or replay of any consumed readiness/Play/recovery notification.

An `idle` loaded brain with restricted reported policy and complete empty
current tracked terminals can produce `evidence_complete_not_activated`.
`notLoaded` retains null policy/trackers and produces `blocked: brain_not_loaded`.
No load, implicit subscription, turn, permission response, cancellation, keeper,
host launch, binding change or model override exists. Active, drifting,
unsupported, nonempty tracker, unknown authentication or permission/input states
fail closed. The no-reload constraint is never relaxed to make a review runnable.

The schema and advertised model intersection are API-shape/catalog observations,
not account entitlement, successful worker tools or runtime acceptance. Loaded
defaults are not active-step grants. An empty current tracker is not historical
cleanup or complete descendant/process safety. Current and historical terminal
safety remain unknown in every report.

## Accounting and authority

Retain the original carried allocation and every old usage/gap. Preserve at least
the full preparation reservation or the larger actual new-turn charge, including
overruns. The conservative future phase ceiling is not a fresh usage sample or
budget grant. Missing/incomplete preparation usage blocks worker readiness;
unknown is never zero. Lifetime coverage is not asserted. An exhausted remaining
allocation also blocks. No allowance, clock or reservation is renewed.

The report cannot unfence normal writes, complete the original readiness,
populate its catalog, review a new mission, admit/issue a worker or start Play.
The prospective worker phase still needs its supported exact review and new
Play, fresh evidence at every effect boundary, current cumulative usage,
repository exclusion, Pause priority and one-shot native creation. This source
does not implement an execution bypass around the preparation fence. Do not
offer a futile executable review when the loaded-only prerequisite is absent.

## Qualification

with labelled synthetic native metadata. Cover loaded/unloaded states, original
record/claim preservation, explicit historical source comparison, stale status,
partial output, overrun/missing usage, policy/identity/account/model drift,
unknown delivery, permission input, source/repository changes and closed RPCs.
Run full local Python discovery and all JavaScript suites/syntax checks. No paid
CI or GitHub Actions are added.

The optional `scripts/qualify_public_host_restart.py --worker-readiness` uses an
already pinned native binary in a disposable home/socket and loopback provider.
The predecessor deadline and brain mailbox publication are explicitly synthetic;
the native load, preparation turn, post-preparation activity, schemas, model/policy/
identity reads and closed connection are real. The worker observation adds zero
loads, subscriptions, turns or provider requests. Fixtures qualify neither the
live binding, account entitlement, actual model compliance nor pilot acceptance.
