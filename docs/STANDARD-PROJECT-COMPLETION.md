# Standard-project completion contract

Owner decision, 2026-09-21: use cooperative native Codex orchestration for
standard projects. Harness remains a separate, stricter milestone. This replaces
the rolling iteration estimate with one acceptance checklist; merged helper PRs
are not acceptance.

## Approved boundary

Manage registered workspace tasks only. Usage is observed, may be incomplete,
and triggers checkpoint stops; it is not complete lifetime accounting or a
provider-enforced cap. Task completion and tracked-terminal checks are not proof
of whole-process-tree cleanup. No paid API or GitHub Actions execution. Two
disposable local Git projects and native Codex tasks are authorized for the pilot.
No live Harness state, repository, automation or installed skill is changed.

## Bundled acceptance

- [x] Exact owner-selected cooperative Play, separate from strict activation.
- [x] Workspace-scoped mission, phase checkpoint, limits and model policy.
- [x] Durable task inheritance, one-shot native effects and explicit recovery.
- [x] Cross-workspace repository exclusion and registered-task capacity.
- [x] Cooperative Pause, retained checkpoint and explicit Resume.
- [x] Observed usage, unknown coverage and conservative task allowances.
- [x] Source/test/result evidence, artifact history and retained native tasks.
- [x] Dashboard controls/status and standard brain operating instructions.
- [x] Local regression suites and rendered dashboard checks.
- [x] Real two-project pilot; report native behavior separately from simulation.
- [x] Consolidated implementation and acceptance report prepared for one PR.

See the [acceptance report](STANDARD-PROJECT-ACCEPTANCE.md) for the real native
sequence, pilot defects corrected, retained evidence and non-guarantees. Manual
merge and rollout to non-disposable workspaces remain separate release steps.

Existing strict run readiness remains diagnostic. No strict enrollment fence,
imported owner, usage baseline, cleanup rule or schema marker can be bypassed by
selecting standard mode. Existing workspaces are never opted in on upgrade.

## Completion semantics

Play grants one reviewed phase, not an unbounded roadmap. At phase completion,
material scope change, insufficient budget allowance or an unresolved native
effect, stop with a checkpoint and a specific next decision. Retain tasks by
default: archive only after separate approval and verified preservation. Native
model/effort selections are requested settings until independently observed;
speed selection is unavailable in the current task-creation interface.
