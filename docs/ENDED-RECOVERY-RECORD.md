# Owner inspection of an exhausted recovery

**Status: source-only inspection adapter. No live installation, runtime repair,
terminal reconciliation, closeout or pilot qualification.**

An accepted completed Pause receipt recovery without a ledger receipt has
consumed its one-shot native attempt. Another host, signature or command name
cannot authorize a resend. The [continuation proposal](ENDED-RECOVERY-CONTINUATION-PROPOSAL.md)
separates inspection, historical-effect reconciliation and eventual closeout.
This implementation covers **only a local owner inspection record**. The
original requests remain unresolved and every execution fence stays in place.

## Owner workflow

The workspace still says **Recovery ended without a Pause receipt**. Its
**Inspect blocked recovery** action opens **Details · Control request history**.
When the saved records meet the narrow eligibility below, that history offers
**Review non-waking recovery inspection**. This is an explicit metadata check,
not another recovery or Help request. It needs an already separately reviewed
host; clicking it does not repair, start or rebind one.

The signed preview identifies the exact ended recovery and current observation
and prominently states **blocked · unqualified**. Confirm its displayed
**confirm non-waking inspection record** button (or that exact phrase in the
same active preview) to retain the local record. The existing authenticated
session, CSRF, project, revision, signature and five-minute preview checks apply.
Confirmation repeats metadata reads and refuses changed evidence. An expired
preview can be refreshed without waking anything. Repeating a saved confirmation
returns its validated historical receipt without host I/O or renewed timestamps.
Vague assent and model text cannot confirm it.

After confirmation, the inspector focuses the short **Owner inspection recorded
· still blocked** outcome, with the reviewed scope collapsed under Details.
The same outcome is retained in control history after reload.
It is not **Received by brain**. No Help/Review/Play progression or safe
checkpoint is manufactured, and the original Pause/recovery still lack receipts.
Missing historical effects need independent reconciliation; this delivery
does not provide that evidence or a terminal closeout adapter.

## Eligibility and read-only boundary

- Only a schema-4 cooperative standard run that is empty, paused and stopping.
  Strict Harness, Brain Stop/handoff, maintenance/admission fences, controllers,
  runners, tasks, packets, merges and other pending controls remain refused.
- The original Pause and queued, owner-confirmed recovery must match the same
  run/phase/brain and original binding. Both retain exact accepted owned delivery,
  completed native turns, closed observers without child events or native
  approval intents, and the restricted resume profile. Unknown delivery cannot
  use this path. Only a missing recovery ledger receipt is covered, not a
  received recovery with a missing checkpoint.
- Pin both native/app-catalog project IDs, workspace, Git checkout, ledger file
  identity/revision, catalog/location hashes and exact native policy. Matching
  names or directories cannot substitute for identities. Require one bound brain
  with workspace-write/on-request and Code Mode disabled.
- Repeated fixed `project/read`, metadata-only `thread/read` (`includeTurns:
  false`), latest `thread/turns/list` (`itemsView: notLoaded`) and current
  `thread/backgroundTerminals/list` reads must agree on that exact completed
  recovery turn, loaded-idle activity and an untruncated empty current tracker.
  Native transcripts, items and prompt/command text are not retained. Unknown,
  unloaded, active, changed, failed or later turns refuse the record. There is no
  thread load/resume, turn start/interrupt, permission response or discovery
  permit in the record's transport.
- A replacement is operator-supplied and separately reviewed before this path.
  Preserve the original binding as historical hash evidence; never connect to it.
  Only the endpoint may differ. Require the unchanged full brain mapping, the
  original PID and separately reviewed launch-claim hash, and repeated fixed
  `ps` metadata proving that PID absent. Pin both bindings and retirement in the
  signed review. This is read-only inspection, not migration of the consumed
  recovery, cancellation or controller release. No unloaded thread is loaded.

## Atomic private record

The existing `/assistant/preview` and `/assistant/confirm` adapters accept the
closed workflow `phase_ended_recovery_record`; there is no raw ledger-submit
route or alternate dispatcher. Ordinary GETs, Help and polling project only saved
availability and do not connect to a host, inspect a PID or refresh evidence.

Confirmation rechecks maintenance, catalog/ledger/endpoint identity, the complete
original run/commands (including usage, gaps and expiry) and fresh unchanged
native observations. In registry-before-ledger lock order, one ledger transaction
retains a hash-addressed private snapshot and the completed local
`standard_ended_recovery_record` command. The snapshot contains the complete
original Pause, exhausted recovery and run, signed request and fresh confirmation
evidence. Only the ledger event/revision and new record change. The kind is not
notifiable and no brain receipt flag is set. Concurrent confirmations retain one
record; interruption before commit rolls both snapshot and receipt back.

`effectOutcome: unknown`, `taskTreeComplete: false` and
`historicalTerminalCoverage: unknown` are explicit, immutable inspection facts.
Current tracker emptiness cannot prove historical diagnostic denial, cleanup or
permission/effect outcome. This record cannot satisfy `phase_close`'s existing
receipt/reply prerequisites, settle an effect, reset usage, extend expiry, Resume
or replay Play, or pass the pilot. A corrupt retained record refuses even
historical receipt recovery.
