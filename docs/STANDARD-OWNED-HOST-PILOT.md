# Standard owned-host pilot: registered tasks, not legacy tree coverage

## Outcome and boundary

Qualify the existing one-shot owned app-server bridge against the owner-approved
`standard_cooperative_v1` phase lifecycle. The
[standard completion contract](STANDARD-PROJECT-COMPLETION.md) manages registered
tasks and tracked terminals; it does not require complete descendants, lifetime
token counters or OS process-tree cleanup. The brain remains the scheduler.

The historical disposable `workspace_pause_v1` Brain Stop remains checkpointing
with missing inventory. Do not clear its stop, rewrite its protocol, treat an
empty ledger as complete native coverage, or resend its old wake. Qualify a
separate standard disposable phase through the existing controls instead.
Complete legacy/strict tree qualification remains a separate roadmap item.

This guide and collector are source delivery, not completed native pilot evidence.
No Play, worker, native approval, host migration, credential change, installation
or notification follows from loading this document or reading dashboard state.

## Explicit registered-task observer

`standard-native-plan` and `standard-native-collect` reuse the current private
standard controller and the reviewed owned-host binding. Only the designated
brain may call them. They never start an app-server, resume a thread, start a
turn, discover tasks, answer approvals, run commands, clean terminals, finish a
task or release ownership. No new dashboard dispatcher or automatic polling is
introduced. Ordinary `standard-state`/dashboard reads only project the saved
report; they cannot collect native evidence.

From the approved source checkout, after `standard-acquire`, prepare the exact
context with private operator-supplied paths (placeholders are not real values):

```text
python3 -m orchestrator.cli --platform PRIVATE_REGISTRY --workspace EXACT_WORKSPACE \
  standard-native-plan PRIVATE_OWNED_BINDING EXACT_RUN_ID
python3 -m orchestrator.cli --platform PRIVATE_REGISTRY --workspace EXACT_WORKSPACE \
  standard-native-collect PRIVATE_OWNED_BINDING PRIVATE_REQUEST_JSON
```

The private request contains exactly `id` (a fresh request UUID), `runId`,
`expectedRevision`, `contextHash` and `bindingHash` from the plan. Plan output
also describes registered targets and the evidence boundary; those descriptive
fields do not belong in the collect request. A changed plan needs a new request,
not edited replay content. Do not commit these files or controller credentials.

Collection rechecks the exact registered standard run, brain, catalog, repository
identities and host binding before and after I/O. It reads only `project/read`,
metadata-only `thread/read` for the bound brain and confirmed registered IDs,
and paginated `thread/backgroundTerminals/list` for those loaded tasks. Native
project IDs and catalog IDs are never interchangeable. Worker reads validate
their registered ID and Git repository/worktree, not a guessed project mapping.
Known foreign registered identities are refused. Pending client IDs are never
passed to a native read. Two repeated reads must agree, including the task's
activity before/after its complete tracked-terminal pages.

`notLoaded`, unsupported activity, missing pages, repeated cursors, mismatched
identities, changing metadata and native failures remain **unknown**, not idle
or zero terminals. A task loaded on a different Codex host may remain unknown
on this socket. Do not resume it merely to manufacture an idle observation;
use the existing brain-supplied `observe` operation only with independently
obtained, supported native evidence and label that source separately.

A successful transaction retains a bounded immutable report and request receipt
in the private ledger. It updates only registered nonterminal task observations
and a report pointer; consumption, attempts, run state and authority are unchanged.
An unavailable sample invalidates an earlier safe-to-finish observation when the
exact collection context still holds. A concurrent Pause/bind/mission/usage or
host change refuses the stale transaction. Replaying a retained request returns
its original time/report without another connection or observation update.

The normal `finish` gate checks fresh idle/finished activity and no tracked
terminals; measured observations additionally require their exact retained
proof. Source/test/result review remains separate. Supplied observations cannot
inherit a measured proof. A missing/corrupt proof is visibly unavailable, not
success. The inspector shows a short saved-check summary; records are under
**Details · Registered native task check**.

Every report explicitly says: registered standard scope only; no complete tree,
process cleanup, token measurement, ownership release or execution authority.
It cannot satisfy `brain-stop-observe`, `brain-park`, managed terminal settlement
or `checkpointInventoryQualified`. Existing legacy and strict evidence rules
are unchanged.
