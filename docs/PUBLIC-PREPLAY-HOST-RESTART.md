# Fresh pre-Play host repair

A later genuine exit of an already issued fresh restart has the separately
reviewed [successor maintenance path](PREPLAY-SUCCESSOR-HOST.md). Only explicit
`prepare --successor` can prepare that distinct version-2 review; the version-1
original-launch-only contract below is unchanged and cannot reuse an ancestor.

`public_preplay_home_restart_v1` is separate operator maintenance for an exited
fresh public host whose isolated home is already signed in. It does not relax
the older transferred-run restart or initial empty-home launch profile. No
transfer, admission, native load, readiness request, turn, permission response,
binding change, Play, recovery or usage reset follows preparation or launch.

## Exact scope

Require the original issued public launch journal and permanent exec claim,
the same pinned monolithic package/home/checkout, and a registered all-standard
schema-1 project with an unchanged reviewed first-phase mission. Dispatch is
paused, with no run/controller/runner/task/queue/decision/continuation/admission,
Stop or successor/quarantine ownership. Require the actual saved Codex catalog
mapping, both separate project IDs, brain, restricted policy and public task/
policy build contracts. Never connect the original endpoint to validate these
saved records. Every retained readiness attempt must have an ended original
owned turn and closed observer, with no unresolved native permission. An
unreceived request needs its real separately retained canceled-readiness
disposition; raw `queued` never becomes a manufactured receipt. Complete
registry/ledger fingerprints and existing private IPC/claims are pinned.

Repeat fixed original-PID absence, bounded process inventory and scoped home
handle checks. Reused PID, matching/ambiguous native binary, open home handles,
stderr, timeout or incomplete reads refuse; never kill/unlink to force a pass.
Absence and closed observers are quiescence checks, not historical effect or
terminal cleanup. The original host's exit cause remains unknown without its
own exit evidence. Do not describe this as a TTL repair or durable service.

The separate signed-in snapshot supports the bounded native state/history,
system skills and exact arg0 helper links of the old scanner, plus an opaque
`models_cache.json`. For the top-level private single-link `auth.json`, inspect
**metadata only** (owner, mode, size and file epoch). Never open, decode, hash,
copy, refresh or replace credential bytes. Preserve that file in place; it is
deliberately absent from the backup. This is neither a portable full-home backup
nor authentication/account/model-entitlement qualification. Backup all other
supported files, including SQLite main/WAL/SHM, as opaque bytes; fsync and verify
the complete archive. No native SQL, lock repair, config editing or restore.
Plugins, hooks, dotenv, foreign sessions, other configuration, unsafe aliases,
special files and unknown entries refuse. The older scanner still refuses
credentials and cached models. Exact native checkout trust may be preserved,
never added, under the original restricted config validator.

## Prepare, review and one launch

Use the clean pinned source and exact private routes. Read commands construct
only read-only route objects, not Registry/Ledger writers:

```text
python3 -m orchestrator.public_preplay_host_restart --platform PRIVATE_PLATFORM --workspace WORKSPACE prepare ORIGINAL_ISSUED_LAUNCH_ATTEMPT ORIGINAL_BINDING_FILE NEW_EMPTY_SOCKET_DIRECTORY NEW_PRIVATE_REVIEW_DIRECTORY
python3 -m orchestrator.public_preplay_host_restart --platform PRIVATE_PLATFORM --workspace WORKSPACE preview NEW_PRIVATE_REVIEW_DIRECTORY/restart.json
python3 -m orchestrator.public_preplay_host_restart --platform PRIVATE_PLATFORM --workspace WORKSPACE exec NEW_PRIVATE_REVIEW_DIRECTORY/restart.json --confirm-hash EXACT_NEW_REVIEW_HASH
python3 -m orchestrator.public_preplay_host_restart --platform PRIVATE_PLATFORM --workspace WORKSPACE status NEW_PRIVATE_REVIEW_DIRECTORY/restart.json
```

The owner reviews one new exact profile/mode/source/home/archive/state-bound
launch hash. It has **no timer expiry**; scope changes invalidate it. A consumed
original launch, transfer, readiness or recovery approval is not reusable.
Preparation creates only a new private non-credential archive/review; it does
not claim or start a host. Keep old sockets, journals, bindings, requests,
dispositions, usage/gaps and earlier pilot claims unchanged.

An exact confirmation creates one exclusive intent, canonical predecessor fence
and permanent exec claim before final repeated checks and same-PID `execve`.
Only the pinned binary and fixed `app-server --listen unix://NEW_PATH/host.sock`
argv with a closed environment are supported. No desktop pipe, credential argv,
provider override, supervisor, detachment or automatic restart is introduced.
An interrupted/failed/unknown attempt remains consumed, including after partial
persistence. Another review directory or touched old journal cannot reset it.
This initial fresh-home repair supports the exact original launch only; it does
not invent a successor launch chain from a failed/unknown attempt.

Status reads only historical private files and never verifies liveness or
retries. A retained `exec_boundary_issued` is not connectivity. Subsequent
read-only native qualification must verify the actual new PID/birth/argv/cwd,
new socket epoch, exact project/brain/latest ended turn and independently
reported policy/account state. An unloaded brain stays unloaded with unknown
policy/terminal coverage. This profile includes no load or binding installation;
the dashboard cutover requires its separate exact review. It does not qualify
the pilot or resume work. The foreground host can still end with its execution
context; no survival across desktop restart is claimed.

## Qualification and rollout

Disposable tests cover original-request/disposition conservation, actual dual
project mapping, build/policy mismatch, private backup and credential metadata,
aliases/unknown entries, unchanged legacy scanner, exact approvals, permanent
claims, drift, interrupted exec, closed observers/permissions, Pause/Stop/run
races and historical non-waking status. Use the real compiled loopback fixture
with `--signed-in-preplay` for same-home restart/readback: synthetic credentials
only, one cold fixture receipt, zero warm loads/turns/provider calls. Neither
these fixtures nor source delivery touches a live host. Run complete local
Python/JavaScript/syntax checks; no Actions, download or paid service.

Source, manual merge, installation, exact launch review, connectivity and
binding cutover remain separate. Back up and preserve private state throughout.
