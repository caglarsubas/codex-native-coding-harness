# One-shot public pilot inspection, not continuation

`public_pilot_inspection_v1` addresses the **current unloaded-brain evidence
deadlock** after a completed one-brain public transfer and separately reviewed
existing-home restart. An unloaded brain reports no actual effective policy and
its tracked terminals cannot be queried as if it were idle. Replaying the
transfer load, Play or recovery is not an inspection mechanism.

This separate operator path permits one exact, owner-reviewed metadata-only
inspection load on the unchanged current host. It never starts a turn. It is not
a dashboard control, dispatcher, host repair, same-run migration, safe checkpoint,
historical cleanup provider, terminal closeout or pilot acceptance path.

## Scope and evidence

Require the completed exact identity/history transfer, issued existing-home exec
intent/claim/fence, verified original opaque backup and unchanged native package.
Validate the live PID, birth epoch, exact binary/listener argv and checkout,
predecessor-PID absence, socket directory and **actual current socket epoch**.
Read original bindings only as preserved bytes; never connect to a retired host.
Historical implementation trees are evidence, not code executed during review.
The new inspection implementation must independently be clean and exactly pinned.

The original schema-v4 standard run must remain empty, unowned and paused, with
no pending controls, native observer delivery, controller, runner, worker, queue,
merge, strict enrollment or Brain Stop. Preserve the exact catalog mapping,
ledger identity, both project IDs, brain, checkout, original received Play and
latest ended turn, all command/receipt/checkpoint bytes, usage/high-water/gaps and
expiry. The existing transfer scope is not broadened. Any scope drift invalidates
the review, including a changed binding, process, source tree or native state.

Read only the fixed restricted config and previously pinned installation/history
prefixes from the native home. Do not enumerate the current home, open/edit SQL,
copy credentials or read `auth.json`. Preserve only existing native checkout trust;
never add it. Authentication is checked with repeated non-refreshing `account/read`
projections, not a login, entitlement test or model request.

Repeat exact project/thread/latest-ended-turn, effective-policy, complete empty MCP
inventory and authentication reads. `notLoaded` requires null/unknown policy and
unknown terminals. Already loaded-idle requires actual workspace-write,
on-request/user review, enforced Code Mode off and a complete empty tracked-terminal
view; it is **observe-only**, never another load or a policy repair.

## Commands and review

```text
python3 -m orchestrator.public_pilot_inspection --platform PRIVATE_PLATFORM --workspace WORKSPACE prepare ISSUED_RESTART_MANIFEST CURRENT_REVIEWED_BINDING NEW_PRIVATE_REVIEW_DIRECTORY
python3 -m orchestrator.public_pilot_inspection --platform PRIVATE_PLATFORM --workspace WORKSPACE preview NEW_PRIVATE_REVIEW_DIRECTORY/inspection.json
python3 -m orchestrator.public_pilot_inspection --platform PRIVATE_PLATFORM --workspace WORKSPACE apply NEW_PRIVATE_REVIEW_DIRECTORY/inspection.json --confirm-hash EXACT_NEW_INSPECTION_REVIEW_HASH
python3 -m orchestrator.public_pilot_inspection --platform PRIVATE_PLATFORM --workspace WORKSPACE reconcile NEW_PRIVATE_REVIEW_DIRECTORY/inspection.json
python3 -m orchestrator.public_pilot_inspection --platform PRIVATE_PLATFORM --workspace WORKSPACE status NEW_PRIVATE_REVIEW_DIRECTORY/inspection.json
```

Preparation/preview perform explicit read-only checks, not a load. Status reads
only retained files and never renews evidence or claims an outcome. The exact new
review is valid **until scope changes**, not for a short wall-clock countdown.
Generic assent, old launch/transfer/Play approvals and model text cannot confirm it.

Apply durably writes an exclusive intent, a canonical ledger-side original
workspace/run/brain/Play fence, and a separate load claim before the optional
native boundary. A different directory, touched file, new host or socket cannot
mint another load allowance. Failed persistence, drift and unknown/interrupted
delivery remain consumed. Recheck native and local scope immediately before and
after the boundary. These cooperative checks do not promise atomic cancellation
of an in-flight inspection when another writer changes state.

Only fixed `thread/resume` parameters are allowed: exact thread/cwd,
`excludeTurns:true`, workspace-write, on-request/user review, Code Mode/goals/apps/
plugins/hooks disabled. No caller-supplied history path, model, provider, prompt,
permission response or arbitrary RPC is accepted. The connection itself permits
at most one load; it cannot issue `turn/start`, `turn/interrupt`, task creation,
membership changes, account login or native approval responses.

Afterward, repeat exact identity/latest-ended-turn, actual policy and current
loaded-idle/complete-empty tracked-terminal metadata. Append a bounded private
observation, not a ledger policy proof or old receipt. Reconcile uses only
read-only methods on the same exact reviewed process/endpoint. It cannot load
again or migrate a claim. A later loaded view does not acknowledge an uncertain
load response: `loadDelivery` stays `unknown` unless the original acknowledgment
was durably retained. If unloaded or unavailable again, refuse without loading.

## Non-goals and next genuine gates

The result records **current** observed policy and tracked terminals, not OS
process cleanup or historical safety. Both current whole-terminal safety and
historical terminal/effect safety remain unknown. The original Play's null policy
profile and admission guard are never backfilled. Usage stays cumulative and the
original expired duration stays expired.

Consequently `migrationQualified`, `resumeAuthorized`, `closeoutAuthorized` and
`pilotAccepted` remain false even after successful inspection. A separately
qualified historical-effect evidence and expired-phase transition/closeout path
is still needed before development can continue. This source does not weaken
those gates, install a binding, replay an effect, acquire/release ownership or
claim the pilot is complete.

## Disposable verification

Run the local Python and JavaScript suites. Focused tests cover exact review,
scope/Pause/usage races, consumed and interrupted claims, directory/endpoint retry
fences, unloaded/active/approval/policy/authentication/MCP gaps, historical endpoint
isolation, credential non-access and complete original-ledger conservation.

`scripts/qualify_public_host_restart.py --inspection --executable EXACT_BINARY
--sha256 EXACT_HASH` uses two sequential disposable native processes on one
temporary home and a loopback-only fake provider. It creates one original fixture
receipt, restarts its own fixture, verifies unloaded policy/terminal unknowns,
performs exactly one fixed inspection load and repeats loaded policy/terminal
reads across a new read-only connection. Inspection/reconciliation must make
zero turns and zero model requests, preserving the original brain/project/ended
turn/history prefix and restricted config. It never touches a live host, home,
ledger, auth store, dashboard or pilot. No external provider or download is used.

Source, local qualification, merge, installation, exact live inspection review,
current inspection, historical evidence and pilot acceptance remain separate.
Quiesce older maintenance writers and retain verified private state backups before
any separately authorized live application. Source delivery installs/confirms
nothing and leaves the paused pilot unchanged.
