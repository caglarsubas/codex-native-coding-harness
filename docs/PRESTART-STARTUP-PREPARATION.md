# A new preparation-only startup, not readiness replay

Source delivery installs nothing, consumes no live approval, loads no live brain
and starts no live turn. Manual merge, safe installation, exact owner review,
application and actual pilot acceptance remain separate evidence states.

## Supported predecessor and purpose

This operator-only path supports the exact empty paused first-phase project and
positive original `authentication_check / deadline_exceeded` diagnostic described
in [the pre-start resolution contract](READINESS-DEADLINE-AND-PRESTART-RESOLUTION.md).
Both original attempted-effect flags must be false. The canonical readiness claim,
version-3 handoff, verified original backup, unchanged native and app-catalog
project identities, reviewed mission, repository, binding and admission/source
lineage are mandatory. Any load, capture, historical native turn, uncertain
delivery or incompatible/partial disposition refuses. Merely missing a result
does not qualify. Original Python bytes are hashed, never imported or executed.

The new authority is **not another readiness request**. Its distinct purpose is
`new_startup_preparation`: one new preparation-only phase with zero workers and
no repository source changes. It asks the existing brain for only its own new
receipt and an inert pilot proposal. It cannot obtain a model catalog, reconstruct
the old receipt or restore the old readiness allowance. All original SQLite
rows—including metadata/revision, old requests, usage, gaps and clocks—remain
unchanged. Old and new terminal safety remain unknown. Existing ownership and
repository holds are neither released nor requalified.

This does not make worker Play runnable. A later development phase needs its own
supported readiness/evidence, exact review and Play. A returned proposal is data,
not executable authority or pilot acceptance.

## Exact review and one attempt

Use the new qualified source with explicit platform/workspace arguments:

```text
python3 -B -m orchestrator.prestart_startup --platform PLATFORM --workspace TARGET prepare EXACT_BINDING ORIGINAL_COMMAND EXACT_ORIGINAL_SOURCE --max-tokens 10000
python3 -B -m orchestrator.prestart_startup --platform PLATFORM --workspace TARGET backup PRIVATE_REQUEST NEW_DISJOINT_BACKUP --writers-stopped
python3 -B -m orchestrator.prestart_startup --platform PLATFORM --workspace TARGET confirm PRIVATE_REQUEST --confirm-hash EXACT_NEW_REVIEW_HASH --backup NEW_DISJOINT_BACKUP --writers-stopped
python3 -B -m orchestrator.prestart_startup --platform PLATFORM --workspace TARGET status
python3 -B -m orchestrator.prestart_startup --platform PLATFORM --workspace TARGET stop --review-hash EXACT_NEW_REVIEW_HASH
```

Save the returned `request` privately, not the outer envelope. Review is valid
until scope changes, not a short wall-clock timer. It binds the complete current
implementation and execution-directory epochs, immutable original source,
original request/claim/backup/sidecar pins, every registered database, Git head
and working-view digest, original binding and repeated actual native metadata.
Moving/replacing the execution source changes this exact review. Preparation
uses only read-only native metadata; it does not create a claim or load/turn.
Backup and status open no native connection and cannot renew an observation.

Only a **new exact owner confirmation** of this preparation scope authorizes
application. Earlier readiness, disposition, launch or binding approvals do not.
Stop older writers and verify actual process exit; the flag alone is not that
evidence. Back up all registered databases with integrity and exact logical
fingerprints, original sidecars, binding and review to a new private disjoint
folder. Never copy native credentials. Application revalidates both complete
scope and backups under registry-then-target locks. A permanent target marker
and external canonical intent precede native connection/load/start. A partial
marker/intent or uncertain acknowledgment consumes the attempt; an independent
local intent anchor also fences raw-state routing if the target marker is lost. New source,
request ID or host cannot rearm it. Normal ledger writes and competing old
controls stay fenced on transaction entry and exit. Missing target marker does
not bypass an external intent.

## Native and sandbox boundary

The same foreground-owned connection performs repeated unchanged metadata reads,
at most one restricted metadata-only `thread/resume` if actually unloaded,
then repeated loaded-idle, actual restricted policy and complete empty current
tracker checks, and one **new** `turn/start`. The policy remains workspace-write,
on-request, user reviewer, Code Mode disabled. Unloaded null policy/trackers are
unknown, never substitutes for those post-load checks. Native scope freshness
remains 120 seconds. Short per-RPC I/O budgets do not weaken it. The original
900-second connection window is fixed and never renewed. Its existing reader
handles only control frames; it is not a dispatcher or independent keeper.

The brain receives a fixed source-pinned standard-library-only helper and a
checkout-local private mailbox. That standalone helper imports no ledger,
registry, credential, socket or native client. It may read the exact handoff and
turn acknowledgment, validate a closed bounded `{receipt, proposal}` result and
publish that result once. It opens no SQL or protected control socket, avoiding
the earlier sandbox control deadlock. The foreground observer pins those files
outside the sandbox, consumes one result, and records only a new private receipt.
Proposal strings never become commands or model/permission/task authority.
The native sandbox remains workspace-write: the helper's closed writes are
enforced, while the no-source-edit instruction is cooperative and checked
against the pinned repository view afterwards, not a path-level OS write filter.
Any unexpected repository change is preserved and fences the outcome; it is
never silently reverted or accepted. These fixtures do not prove model compliance.
Late publication after observed completion, changed files, unknown delivery,
native permission/input, extra task creation, Stop, lost connection, timeout or
missing result leave an incomplete/unknown consumed outcome. No automatic
permission response, cancellation, reconnect, second load or retry exists.

The token reservation is editable in the exact review (default 10,000, maximum
100,000), must fit inside the original reviewed/carried allocation, and grants
no budget increase. It is cooperative, not a hard provider cap. Preserve observed
new-turn token metadata even on failure and explicitly retain missing/incomplete
coverage. Charge at least the full reservation, or the observed amount if higher,
against the conservative future ceiling. Neither missing usage nor a pre-turn
failure is recorded as measured zero. No lifetime coverage is inferred. The old
usage and its admission baseline remain immutable.

Completion closes the original connection. There is no background continuation.
Status distinguishes the new receipt/proposal from the still-missing old receipt;
the UI offers inspection, not readiness retry or Play. Source/fixture success
does not qualify live entitlement, model tool compliance or terminal safety.
